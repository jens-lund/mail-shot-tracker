# Eternal Tomb production tracker

Open `index.html` directly, or visit the published `/eternal-tomb/` page. No installation or build is needed. The seed includes six asset sections, five shots (seven stages each), and five milestones. Nothing is marked complete until the team updates it.

- **Overview:** clickable progress and status counts, current milestone and asset cards. “Due soon / overdue” lists unfinished Must have work due within three calendar days, with links to its task and calendar. Nice to have work stays out of reminders.
- **Assets:** searchable cards with red Not started, yellow In progress, blue Review and green Done tasks. Open the wider task window to edit names, descriptions, due dates, effort and importance. Each numbered subtask has one-click assignee buttons: Jens in light blue, Kevin in purple, or Unassigned. Asset cards show the assignees of their visible tasks. Expand Notes & progress images to upload screenshots/renders at any status, add a caption, inspect the newest image and browse earlier images. These images also appear in Review. Removing a team member clears their assignments while preserving historical comments. Add and remove subtasks freely; removal also removes their feedback after an inline confirmation. Export a backup first if you need to keep a copy.
- **Tasks:** all asset and shot subtasks in one place, with status and effort filters, search, and sorting by importance/deadline or smallest effort first. Small/Medium/Large estimates workload; Must have/Nice to have determines importance.
- **Scope:** All work, Must have only, or Nice to have only. The choice applies to cards, subtasks, progress, status counts, calendar and review queue. A Nice to have section makes all of its subtasks optional, even if a subtask is marked Must have.
- **Calendar:** month grid and deadline agenda for both section deadlines and independently dated subtasks. Select a day, move between months, or click an entry to jump directly to its task. Subtasks without dates do not inherit the section deadline.
- **Review:** only current tasks marked Review, for both assets and shots. Select a task, upload its current images, choose your name, and post comments. Click an image to place a comment marker; keyboard users can focus the image and press Enter to mark its centre. The comment list also names each marker and its position. Resolve comments, request changes (In progress), or approve (Done). Post a draft comment before changing status.
- **Cinematic:** add shots, use Edit shot to change the name, action, duration, camera/lens/movement, needed assets and production tasks. The arrows change story order. Delete moves a shot into Deleted shots, where Restore recovers its tasks, images and feedback. Archived shots leave progress, deadlines and review queues. Layout can begin with placeholders.
- **Version history:** the existing asset versions, angle images, comparisons and feedback remain available separately. Each history row has a trash icon; deletion asks for confirmation and moves it into Deleted versions. Restore brings back its images and comments. The troll starts with an AI-generated concept version; it is not actual production progress.
- **Milestones:** manually reviewed approval gates through final export and backup.
- **Settings:** project title, team, delivery date, latest previs and team saving.
- **Backup:** export/import JSON. Import explicitly replaces the current project after confirmation.

Everyone can view the shared project. Click **Connect GitHub** and use your own personal token with **Contents: Read and write** on `jens-lund/mail-shot-tracker` to edit. The tracker verifies the token's GitHub identity and checks the account's repository write permission before enabling editing. GitHub also enforces the token's permissions on each save. A token cannot grant access its account does not have. Jens can add Kevin and Nico as collaborators with write access in the [repository access settings](https://github.com/jens-lund/mail-shot-tracker/settings/access). The GitHub Contributors list and the display names in this tracker's Team field do not grant repository access.

A previously saved Mail token is reused unless separate Eternal Tomb settings have been saved. The token stays in browser storage and is never included in exports or repository data. Clearing this project's token does not change Mail settings. Once verified, an editor's offline changes remain queued for reconnection. An invalid token or an account without repository write access leaves editing disabled.

One-click **Sign in with GitHub** is not enabled. It needs a registered GitHub App (Contents read/write, installed only on this repository) and a small HTTPS authentication service to perform GitHub's authorization-code exchange, protect the client secret and check collaborator access. GitHub Pages cannot run that service. The token connection provides verified editor access without adding a hosting account. See [GitHub's authentication documentation](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-a-user-access-token-for-a-github-app).

Use the pencil at the top-right of the project banner, asset thumbnails or version images to choose a replacement PNG/JPEG/WebP. The dialog previews your choice before you save. Asset thumbnail changes affect the card and task header only. Replacing a version image keeps its role and linked comments, and also updates the asset thumbnail when that image was used as the cover. Other versions stay unchanged. Create a new version first when you want to retain the earlier image for comparison. Standalone covers and banner uploads are included in team sync and backups.

With a verified editor token, edits are replayed onto the latest `eternal-tomb/data/project.json` using GitHub's SHA concurrency check. Unrelated teammate edits are preserved; simultaneous changes to the same field use the last successful save. Deleted task IDs prevent stale edits from recreating removed tasks. Deleted versions and archived shots reject stale edits until explicitly restored. Recovery keeps uploaded files; deleting an entry does not delete files from the repository.

The visible site checks shared updates every three seconds using authenticated conditional requests, updating only changed data. Read-only visitors check every 15 seconds with a changing public-data URL to reduce cache delays. Open task windows update too, retaining scroll, expanded notes and keyboard focus. **A saved field keeping focus no longer stops live updates.** Checks continue while drafting; unfinished text, feedback, selected uploads and confirmation windows defer drawing, with a “Team updates received” notice. The latest state appears automatically when the draft is completed. Closing a shot/task window also saves its unfinished text fields. Returning to the tab triggers a check, failures retry with backoff and GitHub rate-limit delays are respected. A second browser tab triggers a check when the shared local cache changes. The public repository's data and links remain public. This is automatic polling, not a persistent real-time connection; editor changes normally appear within a few seconds without reloading or waiting for a Pages deployment.

Data-only saves and uploaded images no longer trigger a Pages deployment. Both are read directly from GitHub, so frequent production edits cannot keep cancelling a website-code deployment. Website code changes still publish through the Pages workflow.

Progress counts completed tasks within the current scope. Asset readiness and cinematic completion are separate. Milestones require explicit review; task percentages do not approve them automatically. Existing blocker notes are preserved in backups, while the main workflow uses importance and deadline reminders.

`data/project.json` is the shared source. `seed.js` is its initial offline fallback, including all shot tasks. Generated cave, character-sheet and clothing references live in `images/`; see `CONCEPTS.md` for prompts. They are inspiration, not final production designs.

Uploaded PNG/JPEG/WebP images are resized to a maximum 2000px edge and saved as WebP in browser IndexedDB. A version can contain 64 images; an input image can be up to 15 MB. Without a token, images and feedback are local to that browser. With team sync, images are published to `eternal-tomb/uploads/` before the shared project record is saved. Export backups include uploaded images available on the current browser; shared images from another device retain their repository links. Import restores included images. Do not clear browser data until your changes are synced or backed up.

Task notes and review uploads use the same image storage, team publishing and backup system as asset versions. Each task supports up to 64 images and 500 comments. Earlier project files and backups are upgraded automatically when read; no shared task state is reset.

Serve this folder with any existing static web server for local preview. No build or installation is required. Run the scripts in `eternal-tomb/tests/`: `core.cjs`, `workflow.cjs`, `task-images.cjs`, `sync.cjs`, `live.cjs` and `collaboration.cjs`. They cover schema, scope/date behavior, recovery, shot order/specs, annotation, media, shared saves, live updates and verified editor access. Neutral fixtures keep the tests independent of the team's changing production data.
